## Design Decisions

### 1. Method Organization

- **Grouped by purpose**:
  - "Geometric queries" for spatial/connectivity queries
  - "Node queries by state" for constraint/load queries
- **Rationale**: Clear semantic grouping improves API discoverability

### 2. Alias Method (`getMembersAtNode`)

- **Decision**: Provide semantic alias for `getMembersConnectedTo`
- **Rationale**: "at node" is more intuitive than "connected to" for some use cases
- **Implementation**: Simple delegation to avoid code duplication

### 3. Null Pointer Handling

- **Decision**: Return empty vector for nullptr inputs instead of throwing
- **Rationale**: Consistent with "not found" behavior (returns empty, not error)
- **Example**: `getMembersConnectedTo(nullptr)` returns `{}`

### 4. Region Query Inclusive Bounds

- **Decision**: Use `>=` and `<=` for spatial bounds (inclusive)
- **Rationale**: Standard practice for bounding box queries in CAD/FEM systems

### 5. Filter Methods Return by Value

- **Decision**: Return `std::vector<NodePtr/MemberPtr>` by value (not reference)
- **Rationale**:
  - Results are filtered subsets (not the full collection)
  - Modern C++ move semantics make this efficient
  - Prevents lifetime issues with temporary results
